# SCRUM-30 capacity and provisional quote slice

Base dev HEAD: `7edad61` (PR #70). `GOKUL_FEATURES_DELIVERY_CAPACITY=false` by default; effective only with delivery zones, locality, consent and identity flags. Migration V68 adds rider windows per zone/date/IST time range with positive capacity, bounded reservation count and paused-by-default controls. `BRANCH_MANAGE` configures windows in Branches & settings. Window configuration locks the zone row and cannot lower capacity beneath current reservations. Pausing a rider window or zone removes it from preview.

The customer area check sends locality, six-digit PIN, date, branch and current cart product IDs to the server only after the visitor submits the form. Optional GPS coordinates and free-text landmark stay client-side. The server quote checks exact zone, active branch, products allowed on that branch, date in the IST booking horizon, configured hours, window pause and currently free capacity. It returns only provisional windows with `orderable=false`. It does not verify inventory quantities or reserve a rider, and the current pickup-only order creation and payment APIs remain untouched.

This is still not SCRUM-30 completion. Until then leave all delivery flags OFF and do not promise delivery at checkout.
