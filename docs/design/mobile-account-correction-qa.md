# Mobile accounts and order corrections — QA

No merge or deployment is included. Review on DEV with a test payment provider first.

- At 320, 390 and 640px: profile navigation opens focused pages; each returns to Profile. Rewards shows real available/pending coins, expiry, terms and history. The ₹75 reward requires at least ₹750 eligible food when the redemption cap is 10%, even if its nominal minimum is ₹699.
- At 641px and desktop, and with visual flags OFF: existing profile/navigation, order detail and checkout presentation remains. Guest browsing stays available; private data requires verified owner identity.
- Choose the pickup branch from the compact arrival cards. Confirm the actual branch/address in mobile checkout. Switching branches or changing the saved branch resets that confirmation. Existing cross-branch cart clearing still requires confirmation.
- Complete a sandbox payment, then review cancellation. During CONFIRMED or PREPARING, allow the entire 10 minutes from server-recorded `paidAt`; at the deadline reject it. Collected/dispatched orders are excluded. Additional fees and their included taxes remain retained. Test a lost response and retry: one correction, one inventory/capacity release and one provider refund reference.
- Admin/manager: open a paid order detail, choose a receiving branch and pickup slot and supply an audit reason. Matching prices/charges and available receiving stock/capacity permit transfer before preparation. Changed prices, closed branches, sold-out items, missing stock or full slots leave the original order untouched. Both branches require staff access. Short order number and pickup code must stay identical. Check receiving staff alerts and customer inbox.
- Create an offer in Offers, then open Earned-visit offers. Minimum 0 preserves its current audience; 1/5/20 target the corresponding completed-visit recognition. An unpaid, paid-but-uncollected, refunded or foreign-owner order cannot qualify. Eligible signed-in customers see these offers alongside their other eligible choices.
- Name is optional. Adding a name updates the existing profile without requesting another OTP.
- Optional address assistance uses Google Maps reverse geocoding. Set server-only `GOKUL_GEOCODING_API_KEY` in Render to a restricted Geocoding API key with billing configured. Do not place it in Vercel/browser env or chat. Empty is the default and keeps manual entry working. The customer explicitly consents before coordinates are sent; only the address draft is returned, and nothing is saved until Save. Check/edit house details and postal code. Denial, lookup outage and missing postal code leave manual editing available; each subject is limited to one lookup per minute. Coordinates are not stored.
- PhonePe refund initiation/status use its existing V2 credentials and merchant refund reference. Razorpay refunds send a stable `X-Refund-Idempotency` key; Paytm retains its merchant refund reference. Sandbox-test partial food refunds and an interrupted provider response. Provider failure must remain visible for staff review, never report successful bank credit.
