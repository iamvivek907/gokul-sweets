# Verified pickup handover and online payment fee

Ready-order cards and the order drawer expose **Swipe to hand over** only to branch staff with `ORDER_MARK_PICKED_UP`. Swiping opens a four-digit code dialog; it makes no status request. Staff enter the customer's code and choose **Confirm pickup**. Keyboard and tap confirmation use the same dialog. Wrong codes, cancellation and missing permission leave the order unchanged.

The backend issues a stable, random four-digit code when payment confirms a pickup order, including fully paid occasion pickups. The customer's order page displays it through an endpoint requiring their verified owner session. Staff detail/KOT responses never include the code. A code is consumed in the same transaction as handover; a failed inventory/status transaction restores it. Five incorrect guesses across all staff sessions trigger a 15-minute cooldown. Verification uses the same database connection as the locked order transaction. A dedicated code-rejection exception commits only attempt/cooldown changes before any handover writes; other failures roll back consumption and fulfilment. The protected code response sends `Cache-Control: no-store`. Normal status updates and late collections both require verification. Codes are not sent by SMS; they appear on the customer's order page. Legacy guest order-number access alone cannot read this secret.

Under **Admin → Branches → select branch → Online payment fee**, branch managers can enable a rate from 0–10%, configure its inclusive tax treatment and save after reviewing provider terms/tax treatment. It starts OFF at 0%. New pickup and delivery checkout quotes calculate it from the amount after discounts, including applicable convenience/delivery charges, and show a separate line before payment. It never compounds on itself or earns rebate thresholds. Approved occasion instalment quotations retain their existing pricing.

The accepted quote signs the amount, percentage, tax treatment and settings version; new order snapshots preserve them. Rebate changes reprice the fee using the agreed snapshot. The global tax-off setting gives new quotes a zero fee-tax component. Existing orders and captured payments are not rewritten.
