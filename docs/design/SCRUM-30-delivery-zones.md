# SCRUM-30 coverage configuration, first slice

Base dev HEAD: `8edcae8` (PR #69). `GOKUL_FEATURES_DELIVERY_ZONES=false` hides both endpoints and the admin panel by default. The effective flag also requires the SCRUM-29 locality, SCRUM-49 consent and SCRUM-36 identity flags. An authenticated staff member with `BRANCH_MANAGE` can configure a branch's exact locality and six-digit PIN, IST operating hours, enabled product IDs, active status and rider pause from Branches & settings. Zones start absent and must be deliberately enabled. Product IDs must be active on the branch menu; changes to branch or menu availability fail closed at query time. Exact locality plus PIN matching prevents distance-only inference or a nearby unserved hamlet from appearing covered.

The customer coverage endpoint returns configured area candidates only and always says `orderable=false`. It does not quote a delivery time, take a delivery order, or reserve a rider. Separate delivery capacity, selected service window and a final address/cart quote inside the checkout transaction are required before any serviceability promise. Pickup inventory, payment and checkout are unchanged.

This is a configuration foundation, not SCRUM-30 completion. Follow-up work must wire the customer intake to explicit server validation and verified availability, handle boundary addresses and postal/locality spelling with a reviewed map or area registry, build delivery capacity and reservation with concurrency tests, and smoke DEV flag ON/OFF after manual deployment. Do not enable this flag or mark the story Done on this PR alone.
