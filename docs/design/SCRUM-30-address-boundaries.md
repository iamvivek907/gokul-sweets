# SCRUM-30 reviewed address boundaries

Base dev HEAD: `c940764` (PR #72). V69 stores an admin-approved polygon per delivery zone. `GOKUL_FEATURES_DELIVERY_ADDRESS_BOUNDARIES=false` by default; it requires delivery capacity, zones, locality, privacy and identity flags. BRANCH_MANAGE can enter ordered surveyed latitude/longitude vertices and explicitly mark the polygon reviewed. An edit automatically removes review in the admin form; server validation rejects degenerate, invalid or crossing edges. Unreviewed or missing boundaries fail closed when the flag is ON.

After an explicit action, a customer can provide a manual coordinate pin or permit a one-time device location request. The page holds the device coordinates only in memory until the next check; the backend uses the coordinates in a POST body only to test polygon membership and does not write or log them. The pin is combined with exact locality/PIN, branch, eligible products, daily inventory and rider window checks. A point on the edge is accepted; a nearby address beyond the edge yields no provisional windows. The result still has `orderable=false` and neither stock nor rider is reserved.

Manual locality/PIN without a pin still offers pickup and an area-only preview; a denied device request can be replaced by a manually supplied map coordinate. A future map picker or vetted geocoder should make manual pin placement easier and reconcile actual street addresses. Review polygon accuracy in DEV with branch staff and privacy wording before enabling; the current order schema requires a pickup slot, so delivery checkout and transactional reservations remain a separate SCRUM-30 implementation step.
